## 1. [HIGH — R-38 / R-17, also collides with this repo's own CLAUDE.md rule #1] Fabricated-looking "live" data on the pre-login auth screen

**File:** `public/index.html:567-577` (`.auth-telemetry-card`)

The login modal's brand panel shows a "mini live market preview" card with specific,
realistic-looking numbers: `BBCA · Bank Central Asia +1.8%`, `Smart Money: Akumulasi
Besar (72.4%)`, `MoS: +9.3%`. These are hardcoded static values baked into the HTML, not
fetched — every visitor sees the same numbers regardless of the actual current market,
and they are styled identically to the app's real live widgets (colored badges, mono
font). There is no "contoh/ilustrasi" label anywhere nearby.

This is shown to unauthenticated visitors as the very first thing that establishes trust
in the product, and it is the same category of issue this project has fixed multiple
times before (Foreign Net Buy/Sell widget, fixed earlier today; "TOP SMART MONEY INFLOW"
removed 2026-09-25) — data that looks real but isn't, undermining the "Zero Fabricated
Data" rule the project holds itself to elsewhere.

**Fix direction:** either wire this card to a real cached quote (e.g. last real BBCA
close + last real smart-money score, refreshed periodically), or clearly label it
"Contoh ilustrasi" / "Data ilustratif" so it cannot be mistaken for live data.

## 2. [HIGH — R-32] Two search inputs have zero visible keyboard focus indicator

**Files:** `public/css/main.css:1638-1649` (`.side-search-input`, sidebar search),
`public/css/main.css:3054-3064` (`.cmd-search-input`, command palette search)

Both set `border: none; outline: none;` with no `:focus` or `:focus-within` rule anywhere
in the stylesheet to replace it (verified: no other selector referencing either class
name exists in main.css). Every other text input in the app (`.finput`, `.auth-field
input`, `.cdset input`, `.sm-input`, `.bandar-input`, `.stockchat-input-field`,
`.form-input`/`.cfg-input`) removes the native outline the same way but replaces it with
a border-color change and/or box-shadow ring on `:focus`. These two do not — a
keyboard-only user tabbing into either search box gets no visible indication it is
focused at all.

**Fix direction:** add a `:focus`/`:focus-within` rule to `.side-search-wrap` and
`.cmd-search-header` (or the inputs themselves) that changes border-color and/or adds a
focus ring, matching the pattern already used everywhere else in the app.

## 3. [MEDIUM — R-01 / R-07 / R-10 / R-13, trend-stacking] Landing screen stacks more decoration than the dose caps allow

**File:** `public/index.html:190-543` (`.lp-*` inline styles, `#landing-screen`)

The current landing page has a real, specific identity ("institutional trading terminal
in deep space": starfield, telemetry HUD, coordinates, regime status), which is not the
generic blue-purple SaaS gradient this filter normally flags. But within that identity,
several dose caps are exceeded simultaneously on one screen:

- Background: 2 radial-gradient glow orbs (`.lp-horizon-glow`) + a starfield
  (`.lp-starfield`) + a 1px grid overlay masked to a circle (`.lp-telemetry-grid`) — three
  decorative background layers at once (R-07 dose).
- Glow: the telemetry dot (`box-shadow: 0 0 8px`, infinite pulse), the primary CTA button
  border/hover glow, and the hero card's own glow layer (`0 0 40px rgba(56,189,248,.08)`
  inside a 3-layer box-shadow) — glow on 3+ elements at once (R-13 dose cap is 1-2).
- Glass: `.lp-hero-card` (blur 20px) + `.lp-btn-guest` (blur 8px) — within the 1-2 element
  cap (R-10), noted only because it stacks with everything else above.

None of these are individually banned, but together on a single screen they read as
trend-stacking (Part 1: "Too Much Decoration") rather than a controlled application of
the terminal/space motif.

**Fix direction:** keep the identity, remove one layer of glow (the dot's pulse-glow or
the card's ambient glow, not both) and drop either the starfield or the grid overlay so
the background reads as one deliberate texture instead of three.

## 4. [MEDIUM — dead code, R-33-adjacent] ~480 lines of an entirely superseded landing page sit unused in main.css

**File:** `public/css/main.css:6420-7900` (approx.), classes prefixed `.landing-*`

This block is a complete earlier version of the same landing page — its own comment
literally says `INSTITUTIONAL LANDING PAGE (DRIBBLE TRADING TERMINAL STYLE)`, the same
description used for the current live version's comment in index.html. It has its own
hero, badge, CTA buttons, and a `.landing-terminal-preview` fake-terminal-window
component (`.landing-terminal-topbar`, traffic-light-style header).

Verified via repo-wide grep: none of `.landing-pulse-badge`, `.landing-hero-title`,
`.landing-terminal-preview`, `.landing-btn-primary`, etc. appear in any `.html` or `.js`
file — only in this CSS file. It was replaced by the current `.lp-*` inline landing page
(index.html:190-543) but never deleted, and it also contains its own instance of the
fake-terminal-window pattern (`.landing-terminal-preview`) that would itself be a finding
if it were still live.

**Fix direction:** delete the dead `.landing-*` block from main.css. This also trims
~480 lines off the file (currently 8036 lines, well past the project's 800-line soft
ceiling per file, though this single stylesheet holding the whole app's CSS is a
separate, pre-existing structural decision not in scope here).

## 5. [MEDIUM — R-36, needs verification not proven fabricated] Unverified technical/completeness claims in marketing copy

**Files:** `public/index.html:480,540` (landing telemetry bar); `public/js/38-ai-autonomous-trading.js:1767,1943`

- `ENGINE: DUAL-CORE AI CONFLUENCE` and `ZERO SYNTHETIC DATA ENFORCED` (landing page
  telemetry bar, shown to every visitor before login).
- `SELF-LEARNING QUANT` and `TODAY'S HIGHEST EXPECTED VALUE OPPORTUNITY` badges in the AI
  Autonomous Trading page.

I have not verified whether "dual-core AI confluence" describes a real, documented
architecture, whether the self-learning claim reflects an actual online-learning loop
(vs. a static rule-based system), or whether "zero synthetic data enforced" is true
project-wide (this session alone found and removed one violation of that exact claim in
the Foreign Flow widget). Unlike finding #1, this is not proven fabricated — it needs the
product owner to confirm each claim is real before it ships as fact, consistent with
CLAUDE.md rule #1.

**Fix direction:** for each phrase, either point to the real mechanism it describes, or
soften it to something demonstrably true.
